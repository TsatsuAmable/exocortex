# GOMS integration audit — 2026-09-11

## Finding
GOMS v2 is live on the MacBook at `Documents/aineko-infrastructure/goms-v2`.
Its canonical state is SQLite (`goms.sqlite3`) plus an append-only hash-chained `events.jsonl` ledger.
Neo4j is a rebuildable graph projection at `bolt://127.0.0.1:7687`, installed via Homebrew and launched by `sh.brew.neo4j.plist`.

## What works
- MCP server exposes durable memory, recall, branches, checkpoints, claims, evidence, failures, stats and graph queries.
- Delivery controller writes branches/checkpoints into GOMS.
- Local orchestrator, CLI, commitment gate and delivery controller have produced durable events.
- Neo4j can be rebuilt from canonical SQLite state.

## Actual failure
The ChatGPT conversational surface is not universally connected to GOMS.
Therefore useful decisions and context can remain trapped in chats and the human becomes the continuity bridge.
This is an ingestion/retrieval coverage failure, not a storage-design failure.

## Required invariant
Every cognitive worker or interface must be able to:
1. read relevant GOMS project state before substantial work;
2. emit branch/checkpoint/events during work;
3. persist durable decisions, evidence, failures and artefacts before session termination;
4. recover after worker/session death without relying on human memory.

## Next work
Build adapters for ChatGPT/chat-export ingestion, Manfred read/write control, Obsidian projection and Notion projection.
Add a coverage auditor that reports which active workers/surfaces have read/write connectivity to GOMS and flags orphaned work.
